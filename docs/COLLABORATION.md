# 多 AI 协作流程

仓库是统一版本来源；每个 AI 使用自己的工作目录和任务分支。其他 AI 能否访问
私有仓库，取决于用户对对应服务的授权，不能仅凭仓库地址访问。

## 每次接手

1. 阅读 `AGENTS.md` 和 `docs/CURRENT_STATE.md`，确认当前任务与允许改动范围。
2. 检查 `git status`；若有别人的未提交修改，不覆盖它们。
3. 从最新 `main` 创建任务分支，例如 `codex/path-model-audit`。
4. 一次只处理一个明确问题：动力学、对齐、评估或文档尽量分开。
5. 运行相关自检，写清实际运行的命令、结果和未执行的验证。
6. 提交到自己的分支，经差异审查或 Pull Request 后合并到 `main`。

不要让两个 AI 同时修改同一个克隆目录。也不要把原始数据路径的存在误当成
数据已随仓库上传；本机测量数据需要单独、安全地提供。

## 可直接给另一位 AI 的接手提示

> 请先阅读 AGENTS.md、README.md 和 docs/CURRENT_STATE.md，再检查相关代码。
> 本次任务是：【填写一个具体任务】。请使用独立任务分支，只改相关文件。
> 保留既有实验和算法基线，区分数值正确性与方法有效性。
> 提交时说明改动、测试、局限及下一步，不自动运行完整实验或发布研究数据。

## 大文件与依赖

`data/ring_modes_30.csv` 是模型必需的小型资产，随代码版本管理。原始 MAT/TDMS、
CAD、论文和 `results/` 不进入 Git。`requirements.txt` 是兼容范围，并非完整环境
锁定文件；正式实验需另记录 Python/MATLAB、依赖版本及 Git 提交号。

当前没有设定开源许可证，也没有自动邀请协作者或安装 GitHub App。
